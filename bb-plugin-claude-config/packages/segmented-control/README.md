# @bb-plugins/segmented-control

Примитив дизайн-системы: выбор одного из N, ровно один активен. Палитра
нейтральная («ghost»), как у нативной кнопки bb «Show right Panel» — у дорожки
нет обводки, залит только активный сегмент.

Вынесено из `bb-plugin-projects`, который нарисовал это первым для вкладок
папки и переключателя режима файла. Второй потребитель — переключатель
Read/Write/Raw в [md-doc-view](../md-doc-view) — повод зависеть вниз на один
контрол, а не рисовать третий руками.

## Отличие от версии внутри плагина

Иконка приходит `ReactNode`, а не именем из реестра Hugeicons плагина: реестр
принадлежит плагину, пакет лежит ниже, и общий слой, который тянется вверх за
реестром, общим не является. Свой интерфейс с `IconName` плагин сохраняет
тонкой обёрткой у себя.

По той же причине берутся примитивы `@radix-ui/react-tabs` напрямую, а не
`components/ui/tabs` плагина. `TabsContent` не используется вовсе: это
переключатель, а не набор вкладок — то, что он переключает, рисует владелец.

## Вид — свой CSS, не утилиты Tailwind

Весь вид лежит в [segmented-control.css](segmented-control.css), обычным CSS на
токенах bb. Так он не всегда выглядел: сначала классы были строкой утилит
Tailwind, и это работало ровно там, где проход Tailwind у потребителя эти
классы видел. А `bb plugin build` гоняет его по дереву САМОГО плагина, не по
пакетам, которые плагин импортирует. Итог был такой: в Projects, чьи
собственные файлы используют те же утилиты, контрол был оформлен; в MD Opener,
где утилит нет вовсе, его стиль не попал в сборку ни одной строкой и сегменты
вышли голым текстом; в Cloud Config не хватило двух утилит из набора, и цвет
сегментов оказался чужим.

Общий компонент, вид которого зависит от того, что потребитель написал где-то
ещё, общим не является. Значения в CSS — ровно те, во что компилировались
прежние утилиты, токен в токен, поэтому Projects выглядит как выглядел.

## Зависимости

Одна зависимость — `@radix-ui/react-tabs`, и она в `peerDependencies`.
`clsx` и `tailwind-merge` не нужны вовсе: имён классов два, они постоянные, и
сливать в них нечего.

Сам пакет Radix значением не импортирует, и это сторожит
`git-install.test.ts`. Резолвинг esbuild идёт от каталога импортирующего файла
вверх, установка плагина из git ставит `node_modules` только в папку плагина, а
`@radix-ui/react-tabs` bb не подменяет своим рантаймом. Импорт, написанный
здесь, падал бы с «Could not resolve».

Поэтому три примитива — `Root`, `List`, `Trigger` — импортирует плагин в своём
`libraries.ts` и передаёт обязательным пропом `tabs` типа `TabsKit`. Пакет
держит только `import type`, который esbuild стирает. `devDependencies` нужны
тестам: `test-support/tabs-kit.tsx` собирает набор так же, как плагин.
