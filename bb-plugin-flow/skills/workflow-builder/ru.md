# Конструктор workflow

Workflow — один .js-файл, который запускает `/workflows` Claude Code. Конструктор — раздел Workflows в Claude Config и правая панель, которую открывает чип workflow во Flow, — показывает его деревом и правит. Деревом он открывает только файл, который может пересобрать из этого дерева байт в байт: в конце файла стоит его метка, и дерево, собранное заново, даёт тот же текст. Всё остальное открывается кодом только для чтения с причиной: написан руками или собран конструктором и потом поправлен руками.

Поэтому workflow собирается и правится только через дерево, двумя инструментами:

- `workflow_read { name }` — файл `~/.claude/workflows/<name>.js` как `{ path, tree }` или `{ path, reason, note }`, если конструктор его не читает.
- `workflow_write { tree }` — проверяет дерево, собирает и пишет `~/.claude/workflows/<tree.name>.js`. Дерево с проблемами отклоняется со всеми проблемами по пути узла, и ничего не пишется. Рукописный файл с тем же именем не перезаписывается никогда.

## Порядок работы

1. Правишь существующий workflow — сначала `workflow_read`. Пришло дерево — правишь его и записываешь целиком. Пришла причина — файл написан или поправлен руками: инструмент поверх него не пишет; собери новый workflow под другим именем или скажи владельцу, что файл остаётся кодом.
2. Новый workflow — составляешь дерево по образцу ниже и делаешь `workflow_write`.
3. Потом .js файловыми инструментами не правишь: одна правка — и для конструктора он «code only».

## Дерево

```json
{
  "name": "write-review",
  "description": "Пишет изменение, потом ревьюит и тестирует",
  "phases": [
    {
      "title": "Build",
      "mode": "pipeline",
      "steps": [
        { "type": "agent", "label": "writer", "agentType": "implementer", "prompt": "Implement {{args}}" },
        {
          "type": "container",
          "mode": "parallel",
          "steps": [
            { "type": "agent", "label": "reviewer", "agentType": "reviewer", "prompt": "Review what was written: {{prev}}" },
            { "type": "agent", "label": "tester", "agentType": "tester", "prompt": "Run the tests for: {{prev}}" }
          ]
        }
      ]
    }
  ]
}
```

- `name` — имя файла: строчная латиница, цифры и дефисы. `description` — одна строка, её показывает список workflow.
- Фаза — `{ title, mode?, steps }`. `mode`: `single` (один шаг, по умолчанию), `parallel` (шаги разом), `pipeline` (шаги по порядку, каждый видит результат предыдущего как `{{prev}}`). Фазы результатов друг другу не передают: работа, где шагу нужен ответ предыдущего, — одна фаза в режиме `pipeline`.
- Шаг-агент — `{ type: "agent", label, agentType, prompt, model?, effort?, schema?, repeat? }`. `agentType` — агент, которым идёт шаг (`implementer`, `reviewer`, `general-purpose`, агент плагина `plugin:name`); шаг без него делает workflow невалидным в конструкторе. `model`, `effort` — только чтобы переопределить свои у агента. `schema` — JSON-схема ответа, когда следующему шагу нужны поля, а не текст.
- Группа — `{ type: "container", mode: "parallel" | "pipeline", steps }`, вложенность любая.
- Обход данных — у параллельной группы, которая стоит стадией pipeline: `iterateOver: "<поле>"` запускает ПЕРВЫЙ шаг по разу на каждый элемент `{{prev}}.<поле>` — ответа предыдущей стадии, поэтому у неё нужна `schema` с этим полем-массивом; элемент в промпте шага — `{{item}}`. `iterateInWaves: true` — поле это массив массивов, волна за волной; `maxParallel: N` ограничивает одновременные ветки.
- Повтор — `repeat: { maxLoops, until }` у любого шага, группы или фазы: узел идёт до `maxLoops` раз и останавливается раньше, когда `until` — выражение JS над `result`, последним ответом узла, — истинно.
- Подстановки в промпте: `{{args}}` — вход прогона, где угодно; `{{prev}}` — результат предыдущей стадии, только внутри стадии pipeline и вложенных в неё узлов; `{{item}}` — текущий элемент, только в первом шаге группы с `iterateOver`. В любом другом месте сборщик выбросил бы подстановку, поэтому `workflow_write` такое дерево отклоняет и называет узел.

Что дерево не выражает — ветвление по результату, счётчики, бюджеты, обход задач со своим состоянием, — остаётся рукописным workflow, в конструкторе только для чтения. Скажи об этом владельцу, а не втискивай в дерево.
