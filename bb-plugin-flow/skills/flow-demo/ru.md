# Демонстрация

Владелец видит, что сделано. Демонстрация — отчёт, а не остановка: в bb отправка закрывает этап, и ты сразу идёшь к следующему этапу прогона. Держит работу только этап Утверждение.

## Что показать

- Всё сделанное с прошлой демонстрации, а первая — с начала работы. Разделами, коротко; по разделу на крупную часть.
- Ссылку на каждый результат: файл, задачу, страницу, PR.
- Что не сделано и почему.
- **Менялся код — живой результат в один клик.** Подними то, что сделано, проверь, что отвечает, и дай страницу или команду запуска. Десктопное приложение — команда запуска.
- **Плагин bb** из рабочего дерева сам не поднимается: bb грузит плагин по пути установки. Перенаправить установку на worktree можно одной командой `bb plugin install --yes path:<worktree>`, но это временно и требует вернуть установку на постоянный источник; `bb plugin remove` стирает базу плагина, его не делать. Проще: до мёрджа и шага обновления плагинов живой результат — команда прогона тестов плагина и скриншот; после — сам плагин.
- **Результат откроют на устройстве, которого ты не видел, — проверь его эмуляцией до демонстрации.** Телефон, другой браузер, тёмная тема: подними результат в Browser Automation с эмуляцией этого устройства и пройди тот жест или экран, ради которого работа. «Не проверял» остаётся только для того, что эмулировать нельзя, и называет причину.
- **Чинился баг — шаги, по которым видно, что его нет.** На том же входе, на котором он был, а не на удобной замене.
- Менялись только документы — живого результата нет, так и скажи.

## Как показать

**В BB.** Виджет `ask_decision` с `outcome` вместо setup:

- `stage` — id этого этапа из инструкций хода; `final` — последняя ли демонстрация; `next` — следующий этап, только когда не последняя.
- `done` — что закрыто с прошлой демонстрации; `pending` — что нет, с `why`; `sections` — разделы отчёта `{ title, text }`; `notes` — «Важно знать»: только то, что поможет владельцу принять решение, абзацами через пустую строку — шаги проверки бага, оговорки, которые меняют его выбор; сколько стоял этап, сколько ушло времени, что прошло штатно — не сюда; нечего сказать — поля нет; `tasks` — задачи без `note`: `done: true` — демонстрация показывает итог задачи; перед вызовом переведи её в In Review: `bb tasks update <ключ> --status in_review`, — done она станет в конце прогона; `done: false` — задача, только заведённая в треде. Виджет показывает их в группах «Review» и «Created», каждую карточкой Tasks+, которая открывает задачу в боковой панели треда.
- Менялся плагин — раздел «Ченж-лог» в `sections` с текстом пункта ченж-лога, как он лежит в файле `bb-plugin-<имя>/changelog/<slug>.md`, по-русски и по-английски: владелец видит, что прочтут пользователи, до мёрджа.
- `results` — хотя бы один: `{ label, target }` — файл, путь или адрес; `{ label, command }` — команда, которую владелец запускает кнопкой. Кроме случая `documentsOnly: true`, среди результатов есть живой: `http(s)`-страница или команда.
- Страницу локального сервера отдаёшь через `bb connect expose <port>`; без Connect — `http://localhost:<port>`.
- `documentsOnly: true` — с прошлой демонстрации менялись только документы: спецификация, план, задача, файл прототипа, который нечего запускать; карточка говорит, что живой ссылки нет. Менялся код — демонстрацию без живого результата инструмент не примет.

**Живой результат.** Владелец судит о работе, видя её запущенной, а не читая о ней. Веб — подними dev-сервер или превью в фоне, выполни `bb connect status --json`: есть пара — `bb connect expose <port>` печатает адрес публикации, его и давай; нет — давай `http://localhost:<port>` и скажи об этом в `notes`; ссылка ведёт прямо на страницу, где правка видна, с query или маршрутом, который ставит её в нужное состояние. Десктоп — собери приложение из этого рабочего дерева и дай `{ label, command }`, который запускает эту сборку; одного нажатия «Run in terminal» должно хватить. Перед отправкой запроси каждую страницу и отправляй демонстрацию, только когда она отвечает 200; команду ты один раз запустил сам.

```json
{
  "title": "Демонстрация — прототип",
  "outcome": {
    "stage": "demo", "final": false, "next": "Спецификация",
    "done": ["Ячейка отправки стоит слева от «Отправить»", "Прототип переключает каждую открытую развилку"],
    "pending": [{ "text": "Раздел outcome", "why": "делаю следующим" }],
    "sections": [{ "title": "Ченж-лог", "text": "- ru: Ячейка отправки слева от «Отправить»\n  en: The dispatch cell sits left of Send" }],
    "notes": "На узкой ленте сегменты обрезают подпись.\n\nСветлая тема проверена только на скриншотах.",
    "tasks": [{ "key": "BBPL-1", "done": true }, { "key": "BBPL-2", "done": false }],
    "results": [{ "label": "localhost:5173", "target": "http://localhost:5173/settings" }, { "label": "Десктоп", "command": "cd app && npm run tauri dev" }, { "label": "prototype.html", "target": "docs/assets/x/prototype.html" }]
  }
}
```

После вызова вставь строку директивы отдельной строкой и в том же ходе иди к следующему этапу. Поднятое оставь работать — владелец может открыть его позже; останови его и сними публикацию (`bb connect unexpose <port>`), когда прогон закончился или его сменила новая демонстрация.

**В Claude Code.** Ответ разделами: «Сделано», «Не сделано», «Как проверить». Каждый файл, папка и адрес — markdown-ссылкой. Живой результат — адрес `http://localhost:<port>` поднятого сервера или ровно одна команда запуска в блоке bash. Затем AskUserQuestion «Что дальше?»: «Продолжить» (Recommended), а комментарий владелец пишет в «Other». Получив ответ, останови то, что поднимал.

Нет AskUserQuestion — тот же отчёт и в конце — «продолжить или напишите комментарий», и ход заканчивается.

## Комментарий к демонстрации

В bb комментарий владельца к демонстрации может прийти в любой момент — и когда ты уже на следующих этапах. Ответь на него. Просит правку — возвращаешь работу на этап, где она делается: отмечаешь этот этап начатым через flow_stage, и Flow снимает готовность со всех этапов после него, — проходишь их заново по порядку, с ревью и автоматизациями, до этой демонстрации и присылаешь её снова: иначе правка минует ревью и коммит за ним. Комментарий без правки — ответь одной фразой и продолжай там, где ты есть.

Задачи группы «Review» уходят в done в конце прогона: шаг автоматизации «Задача → done» переводит все задачи, связанные с тредом; не связанную с ним или при flow без такого шага — переведи сам: `bb tasks update <ключ> --status done`.

В Claude Code демонстрация заканчивает ход: «Продолжить» — идёшь к следующему этапу; комментарий — как выше.
