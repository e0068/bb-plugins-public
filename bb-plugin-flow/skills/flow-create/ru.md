# Создание flow

Flow — таблица этапов: тред, идущий по flow, получает этапы в инструкциях хода, бриф показывает их владельцу, прогресс над композером отмечает пройденные. Первый flow в списке — flow по умолчанию: по нему идут треды, где flow не выбран.

## 1. Прочитай, что есть

**Есть `read_flows` (тред bb с плагином Flow).** Он отдаёт flow по порядку с этапами, имена навыков каталога, id исполнителей и id шагов встроенной автоматизации. Этап ставишь только из этого каталога: навыка, которого нет в ответе, во flow не бывает — `save_flow` его отклонит.

Инструментов нет в треде, начатом до установки плагина. Тогда — раздел 5.

Похожий flow уже есть — скажи владельцу и предложи изменить его, а не заводить второй с тем же смыслом.

## 2. Разложи работу на этапы

Этап — шаг работы, у которого есть свой итог или своя остановка. Порядок в таблице — порядок в прогоне.

| Что нужно работе | Этап | Как в `save_flow` |
| --- | --- | --- |
| Снять развилки до начала | Вопросы | `{ "kind": "questions" }` |
| Согласовать «Готово, когда» | Критерии | `{ "kind": "criteria" }` |
| Дать владельцу выбрать этапы, исполнителей и бюджет | Выбор этапов | `{ "kind": "select" }` |
| Показать сделанное и получить «продолжай» или «на доработку» | Демонстрация | `{ "kind": "demo" }` |
| Шаг по навыку | Этап-навык | `{ "kind": "skill", "skill": "<навык из каталога>", "name": "<название этапа>" }` |
| Шаг без агента | Автоматизация | раздел 3 |

- Вопросы, Критерии и Выбор этапов стоят в начале, в этом порядке: бриф собирает их в один.
- Демонстрация — после этапа, чей итог владелец должен увидеть до того, как работа пойдёт дальше, и в конце.
- Этап-навык — навык из каталога `read_flows` под шаг работы. Какие навыки владелец ставит на какие шаги — задача, прототип, спецификация, план, реализация, ревью, тестирование, исследование, воспроизведение, черновик документа, — видно в этапах существующих flow в `read_flows`: бери оттуда, а не подбирай похожий по имени. Шаг, которого у работы не бывает, во flow не ставь: необязательный для конкретной задачи шаг снимается на Выборе этапов, а не удаляется из flow.
- Описание flow говорит только, когда flow брать: «Когда брать» и «Не брать», две-три фразы. По описаниям агент выбирает flow треду, созданному с «Автоматически», и они стоят в инструкциях каждого такого треда. Этапы, их навыки и исполнители в описании не пересказываются: агент получает их из `choose_flow`, владелец видит в таблице.
- Исполнители этапа — id из каталога: `"executors": ["agent:tester"]`. Сам агент треда исполняет любой этап всегда, его не пишут. Ставь исполнителя, когда работа за ним больше, чем стоит передать её субагенту: реализация, ревью, прогон тестов.
- Встроенный этап получает свой навык полем `skill`, только если владелец его назвал; без поля — навык вида по умолчанию.
- `id` и `name` можно не писать: id — по виду или навыку, название — английское название вида или имя навыка. Названия flow и этапов — по-английски, как у остальных flow, если владелец не назвал другие.
- У этапа могут быть под-этапы, которые включаются и отключаются в прогоне вместе с ним, — например, автоматизация repoint перед Демонстрацией и возврат установки после неё. Под-этап получает `"parent": "<id этапа-владельца>"`, а владельцу тогда нужен явный `id`. Под-этапы стоят вплотную к владельцу: стоящие выше идут до него, ниже — после. У под-этапа нет номера и своих под-этапов; владелец — этап верхнего уровня. Галочка владельца на Выборе этапов и в полосе прогресса переключает всю связку, у под-этапа есть и своя. Flow с под-этапом не рядом с владельцем не сохраняется.

## 3. Автоматизации

Автоматизацию исполняет сам Flow, без агента: как только агент отметил этап перед ней, Flow выполняет подряд стоящие автоматизации. Упавший шаг останавливает цепочку и ждёт «Повторить» или «Пропустить» владельца. Ставь автоматизацию сразу за этапом, после которого она должна пойти.

**Встроенная автоматизация Flow** — `{ "kind": "skill", "name": "Publish", "automation": { "source": "flow", "steps": [...] } }`. Шаги из `read_flows`, в порядке исполнения:

| id | Что делает |
| --- | --- |
| `git.commit` | Commit |
| `git.fast-forward` | Перемотать ветку треда на main |
| `git.create-pr` | Открыть PR через API GitHub, без push |
| `bb.tasks-in-review` | Задачи треда → in_review |
| `files.bump-major`, `files.bump-minor`, `files.bump-patch` | Поднять версию в `package.json` |
| `git.merge` | Смёрджить PR |
| `git.pull-main` | Подтянуть локальный main |
| `bb.reinstall` | Обновить плагины bb из git |
| `bb.tasks-done` | Задачи треда → done |
| `bb.archive` | Архивировать тред |

**Скрипт.** Нужного шага нет — пишешь скрипт и ставишь его шагом той же автоматизации: шаг `"script:<id>"`, скрипт — в `scripts` того же этапа.

```json
{ "kind": "skill", "name": "Lint and commit",
  "automation": { "source": "flow",
    "steps": ["script:lint", "git.commit"],
    "scripts": [{ "id": "lint", "name": "lint.sh", "content": "#!/bin/sh\nset -e\nnpm run lint\n" }] } }
```

- Скрипт хранится содержимым в самом flow, а не файлом: `content` — весь скрипт, до 200 000 символов. Правка скрипта — новое сохранение flow.
- Первая строка — shebang, иначе скрипт идёт через `sh`. Flow запускает его в рабочем дереве треда; id треда и окружения — в `BB_THREAD_ID` и `BB_ENVIRONMENT_ID`.
- Код 0 — шаг пройден, последняя строка вывода видна под шагом. Любой другой код — шаг упал, владелец видит хвост вывода. Скрипт, который шёл дольше 10 минут, останавливается.
- Скрипт не спрашивает ничего у терминала и не ждёт ввода: его некому ответить. Шаг, который нельзя безопасно повторить, делай идемпотентным — «Повторить» запустит его заново.
- `id` скрипта — латиницей, свой у каждого скрипта этапа; `name` — имя файла, оно подписывает шаг на странице.
- Перед сохранением прогони скрипт руками в рабочем дереве и убедись, что код выхода и вывод такие, как нужно.

**Этап Action** — `{ "kind": "action", "name": "Publish", "automation": { "source": "flow", "steps": [...] } }`: те же шаги, но исполняет их не Flow сам, а владелец кнопкой в баннере прогресса, по шагу за нажатие. Прогон на таком этапе останавливается и ждёт владельца; пока шаг идёт, на кнопке лоадер, упавший шаг показывает ошибку и «Повторить» — «Пропустить» у Action нет. Когда шаги кончились, этап закрыт, подряд стоящие автоматизации идут сами, а перед этапом навыка Flow будит агента. Ставь Action вместо автоматизации там, где владелец должен решить сам: коммит, PR, мёрдж, выкладка. Исполнителей у вида нет — с ними `save_flow` этап отклонит.

**Автоматизация плагина Automations** — когда нужное уже собрано там правилом: `{ "kind": "skill", "automation": { "id": "<id строки>", "name": "<имя строки>" } }`. Id и имя бери из `pr_automation_read`; Automations должен быть включён, иначе этап упадёт с этой причиной.

## 4. Сохрани и проверь

`save_flow` — один flow за вызов: `{ "name", "description"?, "stages", "id"?, "position"? }`.

- Без `id` — новый flow; с `id` существующего — замена целиком, поэтому сначала возьми его этапы и описание из `read_flows` и пришли всё: не присланное описание стирается.
- `position: 0` ставит flow первым — flow по умолчанию. Меняй flow по умолчанию, только если владелец так сказал.
- Отказ перечисляет все проблемы сразу, с номером этапа: исправь и пришли снова. При отказе ничего не сохранено.
- Ответ — сохранённый flow и порядок всех flow. Сверь этапы с тем, что собирал, и что остальные flow на месте.

Владельцу в отчёте — название flow, этапы по порядку одной строкой и место в списке. Открытая страница Flow показывает новый flow сама.

## 5. Без инструментов

Обычный Claude Code или тред bb, начатый до установки плагина: собери таблицу — №, вид или навык, название, исполнители, автоматизация с шагами и текстом скриптов — и попроси владельца собрать flow на странице Flow: «Новый flow», этапы кнопками под таблицей, скрипт — «Добавить скрипт…» в меню шагов автоматизации.
