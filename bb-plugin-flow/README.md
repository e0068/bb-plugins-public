# Flow

Агент спрашивает владельца не прозой, а виджетом в ленте треда: одно окно со всеми вопросами, у каждого варианта развилки — что произойдёт, примерная цена и риски, рекомендация агента помечена, к развилке всегда можно ответить своё. Ответ уходит агенту одной репликой, а виджет остаётся в истории с отмеченным выбором. Ответ, после которого в прогоне не осталось ни одного этапа агента, ему не уходит вовсе: этапы закрываются, автоматизации за ними Flow ведёт сам, и хода агента не начинается — если только владелец не приложил к ответу комментарий или картинку.

## Что внутри

- Инструмент агента `ask_decision` и навык `flow`: любой вопрос, уточнение, развилка и непонимание идут через них.
- Директива `::decision{id="dec_…"}` — на её месте в сообщении агента рисуется виджет.
- Вопросы второй части: `fork` (развилка с описанием и добавкой), `pick` (несколько ответов), `confirm` («правильно ли я понял»), в уточнении — `yesno`.
- Страница Flow в левом меню bb: несколько flow лентой в начале страницы — не помещаются, лента листается вбок, — создание новым flow по иконке Плюса в её конце, удаление внизу страницы с подтверждением; страницу вместе с лентой листает её корень целиком, без рамок со своей прокруткой внутри; выбранный flow живёт в адресе панели, поэтому ссылка открывает свой flow, а «назад» и «вперёд» ходят по выбору; у каждого flow своя таблица этапов с перетаскиванием. На узком экране таблица перестраивается в колонку, а её списки — исполнение с навыком, вид этапа, шаги автоматизации — открываются нижней шторой ([components/ui/field-overlay.tsx](components/ui/field-overlay.tsx)) вместо всплывашки, прижатой к полю. Этап — навык с названием и исполнителями (агенты и workflow) или встроенный вид. Исполнители стоят тегами через «или»: этап ведёт один из них — того, кого владелец выберет в виджете; первым по умолчанию стоит Main Agent — агент, который ведёт тред. Крестик снимает Main Agent, когда у этапа есть другой исполнитель, а пункт Main Agent в меню исполнения возвращает его; снятый Main Agent пропадает из исполнителей этапа в инструкциях агенту и из выбора исполнителя в виджете, а снятый последний исполнитель возвращает его сам. Шаги скрипта стоят тегами через шеврон вправо — они идут один за другим. Плюс исполнения стоит после последнего тега. Этапы двух видов: агентские — их ведут Main Agent, субагенты, workflow или виджет — и скрипты — шаги, которые исполняет Flow; вид выбирается кнопкой под таблицей — «Добавить этап» или «Добавить скрипт», — и меню исполнения у каждого своё: у агентского этапа «Навык · Субагент · Workflow · Виджет», у автоматизации Automations — только навыки, у скрипта — запуск и шаги. Шаблоны этапов тоже разложены по видам: шаблон скрипта — в меню «Добавить скрипт». Встроенные виды: Вопросы, Definition of Done, Выбор этапов, Демонстрация, Утверждение; встроенные виды ставятся сколько угодно раз пятью кнопками под таблицей. Строка перетаскивается за номер: верхняя и нижняя четверть целевой строки ставят её над или под ней, две средние делают её под-этапом целевой — до неё или после. Под-этап стоит без номера, со скобкой к владельцу, и включается в прогон вместе с ним: галочка владельца на Выборе этапов и в полосе прогресса переключает всю связку, а своя галочка под-этапа видна в раскрытом владельце. Под-этап в таблице стоит без иконки и названия. Этап без навыка и исполнения, но с под-этапами — заголовок: своей работы у него нет, её несут под-этапы. Иконка в поле названия, у его левого края, — кнопка: по клику подборка иконок Hugeicons с поиском, выбранная видна в таблице, в виджете и в полосе прогресса, «По виду» возвращает иконку вида. Списки таблицы не уходят за край окна — у края открываются вверх и сдвигаются внутрь — и не выше 70% его высоты. Работа встроенного этапа — в его навыке: по умолчанию `flow-questions`, `flow-criteria`, `flow-stage-selection`, `flow-demo`, `flow-approve`, в таблице встроенному этапу ставится любой. Колонки строки: название и исполнение. Навык ставится на вкладке «Навык» меню плюса — поиск, навыки группами по источнику, свой навык по имени Enter — и стоит первым чипом «Навык: имя» (по-английски «Skill: имя») с крестиком; у скрипта и Action навыка нет — их исполняет Flow. Встроенный этап (Вопросы, Definition of Done, Выбор этапов, Демонстрация) выглядит иначе: имя зафиксировано текстом, а в исполнении — только тег его навыка «Навык: имя», без креста и без плюса; тег открывает навык в правой панели. Flow, добавленный этапом, стоит связкой строк: в первой — только имя вложенного flow, ниже — по строке на каждый его этап с названием текстом и чипами только для чтения. Каждый чип с файлом кликабелен и открывает файл в правой панели bb: навык — SKILL.md, агент — его .md или .toml, workflow — .js, шаг своего скрипта — снимок текста скрипта; Main Agent и шаги Flow файла не имеют. Файла не нашлось — надпись «Файл не найден» под чипами. Навыки плагин везёт сам в [skills](skills) — по-английски, с русской версией `ru.md` рядом; свой одноимённый навык в `~/.claude/skills` (или в `.claude/skills` репозитория) важнее плагинного. Навыки работают и в обычном Claude Code — там вопросы идут через AskUserQuestion. Новый flow собирается из четырёх встроенных этапов: этапы-навыки владелец добавляет сам, из своих навыков. Под названием flow — описание: когда выбирать этот flow. В кнопке flow композера первым пунктом стоит «Автоматически»: сообщение владельца в таком треде ждёт в очереди с подписью «Выбираю flow», пока скрипт [scripts/choose-flow.sh](scripts/choose-flow.sh) один раз вызывает модель без треда — `claude -p` или `codex exec` — с правилами навыка [skills/flow-choose](skills/flow-choose/SKILL.md), «Без flow» и описаниями всех flow; модель отвечает id flow. Тред получает flow, пустой прогон и модель flow, и сообщение уходит агенту уже с этапами в инструкциях хода. Первым пунктом выбора стоит «Без flow» с описанием «когда flow не нужен» — его владелец правит на странице Flow, в первой строке списка, которую нельзя удалить или переставить. Модель выбрала «Без flow», не ответила за 90 секунд, вернула неизвестный flow или CLI на машине нет — тред идёт без flow; сам агент треда flow не выбирает. Старый корневой навык `~/.claude/skills/flow/SKILL.md`, который писали прежние версии, плагин при запуске убирает — иначе он перекрывает навык `flow` плагина. В настройках плагина — общая минимальная ширина кнопки этапа. В виджете части подписаны бирками вида; по кнопке на этап: взять ли его в ближайший прогон, кто исполняет и сколько это стоит, ссылки на сделанное — пройденный этап не снять.
- Демонстрация: на этапе Демонстрация агент кратко показывает всё сделанное с прошлой демонстрации со ссылками и идёт дальше — отправка виджета закрывает этап, и ни агент, ни автоматизации за ним не ждут ответа. Владелец может написать комментарий в любой момент: он приходит агенту в идущий ход. Комментарий с правкой агент возвращает на этап, где она делается, отмечая его начатым: все этапы после него теряют готовность, и работа проходит их заново — ревью, автоматизацию коммита и саму Демонстрацию; деньги и минуты прошлого прохода складываются с новым в строке этапа и в итоге прогона. Если менялся код, в Демонстрации есть живой результат: страница поднятого сервера (через `bb connect expose`, без Connect — localhost) или команда запуска десктопного приложения — блок команды с кнопкой «Выполнить в терминале». Без живого результата инструмент итог не примет, если агент не отметил, что менялись только документы. У виджета Демонстрации — карточка, поле комментария и одна кнопка «Отправить комментарии», выключенная без комментария. Нашёл агент по ходу работы проблемы — например, отвечая на вопрос по flow Answer, — он рекомендует для них flow, и перед кнопкой встают модель, Flow и «Исполнять»: рекомендованный flow помечен ✦, его можно сменить на любой; «Отправить» уводит работу в выбранный flow — в этом треде или в новом, как выбрано в «Исполнять».
- Утверждение: единственный этап, который держит работу. У виджета — только поле комментария и ряд кнопок, без карточки: что утверждается, называет заголовок, а сводку «что утверждено раньше, что сделано с прошлого утверждения, что дальше» агент пишет в виджеты перед ним ([skills/flow-approve](skills/flow-approve)). Пустой комментарий — кнопка «Продолжить» («Завершить» у финального), прогон идёт дальше; написанный — «Отправить комментарии», не утверждено: агент переделывает этап перед утверждением и присылает его снова. Везде ещё комментарий работу не держит: к ответам на вопросы с комментарием «Ко всем вопросам» агент получает строку «о неясном спроси, понятное делай». Строка Definition of Done в полосе прогресса раскрывается и показывает утверждённые пункты треда.
- Кнопки модели и Flow: в нижнем ряду виджета перед «Исполнять» — квадратные, пока выбор текущий, и широкие с названием при другом выборе или предложении агента (✦). В колонках галочка — у выбранного, ✦ — у предложения агента, «Сейчас» — у текущего, когда выбран другой. Другой провайдер сам ставит «Новый тред»: провайдера у живого треда bb не меняет. Модель и effort ставятся треду, flow — переходом.
- Агент flow: на странице Flow у каждого flow и у строки «Автоматически» — блок «Агент»: своя модель с effort выбором модели bb и стартовое сообщение. Тред flow стартует с его моделью (если провайдер тот же) и стартовым сообщением невидимой инструкцией сессии; у строки «Автоматически» блок задаёт модель, которая выбирает flow (по умолчанию Claude Code с Sonnet), а новый тред получает модель и стартовое сообщение выбранного flow до первого хода; тред, где flow выбран заново после завершённого прогона, получает модель, а стартовое сообщение — нет: живая сессия своих инструкций не меняет.
- История прогонов: первая вкладка ленты в начале страницы Flow — «История» с иконкой часов, адрес панели `flows/history`. Список всех завершённых прогонов всех тредов, свежие сверху: тред (ссылка открывает его; у удалённого — «Тред удалён» без ссылки), flow (ссылка открывает страницу flow; у удалённого flow — текст без ссылки; итоги, замороженные до того, как в них стали хранить id flow, находят живой flow по названию), день и окно времени, минуты работы, деньги, этапы «сделано/всего»; строка раскрывается в тот же итог, что под виджетом в ленте. Итог замораживается сервером в момент завершения прогона — на правке, которая его завершила, и при запуске плагина для прогонов, завершённых раньше, — поэтому прогон не пропадает из истории, даже если тред после завершения никто не открыл. Лента вкладок листается вбок, когда места не хватает; раскрытый прогон показывает этапы целиком, а всю историю листает страница.
- Завершённый прогон: когда в прогоне не осталось ни одного этапа впереди, идущего или упавшего, баннер уходит с композера, а в ленту встаёт блок итога под карточкой последнего виджета — «Прогон завершён», окно времени, плитки (исполнители с раскрываемым списком, работа и расход против плана, простой в ожидании владельца) и тот же прогресс-бар, свёрнутый и разворачиваемый в этапы со ссылками. Итог замораживается под своим виджетом, поэтому следующий прогон его не стирает. Само завершение агенту ничего не шлёт и хода не начинает.
- Flow с первого сообщения треда: тред, которому передали работу ответом на виджет, ещё до первого хода получает flow исходного треда и ведёт его прогон — агенту flow выбирать не нужно; любой другой новый тред с выбранным flow сразу получает пустой прогон.
- Следующий прогон в том же треде: после завершённого прогона контейнер состояния Flow над композером предлагает flow для следующего — по умолчанию «Автоматически». Сообщение владельца уходит агенту сразу, без придержания: оно начинает новый прогон выбранным flow.
- Прогресс flow над композером треда: «сделано/всего», значок идущего этапа, сегменты этапов и план; тап раскрывает этапы с потраченным временем, деньгами и ссылками. Агент отмечает этапы инструментом `flow_stage`. Результат-файл задачи (`docs/tasks/<статус>/<слаг>.md`) у треда с flow получает в шапку блок `flow` с id и названием flow — по нему Tasks+ показывает в карточке задачи ссылку на страницу flow; штамп пишется, только если меняет файл, и сбой записи отметку не роняет. Сегмент этапа, на котором идёт работа — ход агента или прогон автоматизации, — приглушённо мерцает, а значок этого этапа стоит слева от полосы; значок этапа — тот же, что на странице Flow: выбранный владельцем, а без него — по виду, у этапа навыка — книга, кто бы его ни вёл; тем же значком этап стоит и под графиком сессии Token Usage Analytics; у исполнителя-агента в виджете и настройках — маленький логотип его провайдера в квадрате; простой агента на этапе не мерцает; поверх сегмента идущей автоматизации мерцает её значок — квадрат, от которого стрелка идёт к квадрату, под её строкой — шаги, у упавшего — ошибка, «Повторить» и «Пропустить».
- Сообщение в чат вместо ответа: пока виджет ждёт ответа, сообщение владельца в чат возвращает виджет агенту — значок ожидания гаснет, виджет в ленте сворачивается в строку «вернулся агенту», а агент учитывает сообщение и присылает виджет заново. Выборы, отмеченные в возвращённом виджете, стоят в новом там, где вопрос и вариант остались теми же; правки пунктов Definition of Done — по тексту пункта. Этап закрывает только отправка виджета кнопкой.
- Значок в левой панели: тред, который ждёт владельца на Вопросах, Definition of Done, Выборе этапов или Демонстрации, показывает значок этого этапа; тред, где сейчас идёт работа, — приглушённо мерцающий значок этапа (логотип провайдера исполнителя, у субагента — в квадрате): этап навыка — только пока агент работает, автоматизация — пока идёт прогон; упавшая автоматизация — ровный значок автоматизации в тоне ошибки. Тот же значок у автоматизаций на странице Flow и в виджете — и у шагов Flow, и у автоматизаций Automations.
- Этап Action: кнопка «Action» ставит этап с теми же шагами, что и автоматизация, — шаги Flow, скрипты, автоматизации Automations, — но исполняет их не Flow сам, а владелец. Прогон, дойдя до такого этапа, останавливается: в баннере прогресса видна кнопка первого незакрытого шага, на время исполнения на ней крутится лоадер и повторно её не нажать, а после завершения показана кнопка следующего. Свёрнутый баннер показывает ждущий шаг строкой под шапкой. Упавший шаг показывает ошибку и «Повторить»; когда шаги кончились, этап закрыт, подряд стоящие автоматизации идут сами, а перед этапом навыка Flow будит агента.
- Автоматизации: кнопка «Автоматизация» ставит встроенную автоматизацию Flow — шаги тегами (переименовать тред, план → задача, Commit, подтянуть ветку к main, открыть PR, задача → in_review, Bump major, Bump minor, Bump patch, смёрджить PR, подтянуть main, обновить плагины с гита, факт → задача, задача → done, архивировать тред; тег бампа ставится между открытием PR и мёрджем, обновление плагинов — после мёрджа), их можно добавить, убрать и переставить. «Добавить скрипт…» в том же меню берёт файл: его содержимое хранится в автоматизации, а шаг называется именем файла; Flow запускает скрипт в рабочем дереве треда — с shebang своим интерпретатором, без него через sh, с `BB_THREAD_ID` и `BB_ENVIRONMENT_ID`; ненулевой код выхода или 10 минут без завершения — шаг упал, в ошибке хвост вывода; запущенное скриптом в фоне шаг не держит, а по таймауту останавливается вместе со скриптом; «Сохранить этап шаблоном» в меню «⋯» строки этапа сохраняет этап целиком шаблоном — название, навык, иконку и исполнение, — а «Добавить этап» ставит шаблон в любой flow, крест в его меню убирает шаблон; «Преобразовать во Flow» в том же меню уносит этап с под-этапами в новый flow с именем этапа, а на его месте оставляет строку «Flow» нового flow — этапы получают id со строкой «Flow» впереди, поэтому тред, уже прошедший такой этап, увидит его несделанным; этап, чей вынос поставил бы мёрдж или бамп раньше «Открыть PR», не преобразуется, и под пунктом видна причина; наборы шагов, сохранённые прежней закладкой, остаются в меню исполнения; «План → задача» пишет в задачи треда Planned Time, Budget и Limit — бюджет, с которым владелец отпустил прогон, — а «Факт → задача» пишет Actual Time и Cost: активные минуты и доллары закрытых этапов прогона, сложенные по всем прогонам, что вели задачу, причём повтор шага заменяет вклад своего прогона, а не прибавляет его второй раз, а прогон с несколькими задачами делит свои числа между ними поровну и округляет вниз — в сумме задачи не показывают больше, чем потрачено; тред без задачи и прогон без бюджета проходят оба шага зелёными; факт ставят до Commit этапа, который увозит задачу в main; оба шага встают во flow сами при первом запуске Flow из main — план за «Переименовать тред», факт перед «Задача → done», — а в превью из дерева треда не встают: сборка без этих шагов не прочла бы такие flow; время и стоимость прогонов, прошедших до шага, дописывает команда `bb flow-spend backfill` из треда — файлы задач ложатся в его дерево, `--dry-run` только показывает, что запишется, `--verbose` выводит строку на каждую пару «прогон — задача», уже посчитанный прогон второй раз не пишется, а задача с числами, которые вписал агент, их сохраняет; Автоматизации исполняет сам Flow, без агента: когда агент отметил этап перед ними, Flow выполняет подряд стоящие автоматизации и агенту ничего не шлёт; упавший шаг останавливает цепочку и ждёт владельца. Секция настроек «Автоповтор автоматизаций» — общая на все flow: «Retry in» — через сколько секунд Flow повторит упавший шаг сам (0, по умолчанию, — не повторять), «Попыток» — сколько раз подряд (по умолчанию 3, 0 — пока не пройдёт); пока повтор назначен, у упавшего шага видно «повтор через N с», а «Повторить» и «Пропустить» снимают его; повтор владельца возвращает шагу все попытки, следующий шаг начинает со своих, шаги этапов Action сами не повторяются; переключатель «Реплика агенту после последней попытки» (по умолчанию выключен) велит Flow написать агенту треда, что упало, когда последняя попытка не прошла и шаг ждёт владельца, а поле под ним — наказ агенту в этой реплике, например «пойми, в чём проблема, и сообщи мне» или «почини, если понятно, что делать». Шаги бампа версии и мёрджа работают по номеру открытого PR, поэтому в меню шагов они недоступны, пока раньше по flow не стоит «Открыть PR», а коллекция с таким порядком не сохраняется вовсе — отказ приходит и странице, и инструменту `save_flow`. Каждое падение шага остаётся в записи прогона: «Повторить» и «Пропустить» снимают ошибку, но историю падений не стирают. Код шагов — общий с Automations пакет [packages/automation-steps](../packages/automation-steps), так что встроенные автоматизации работают и без Automations. Flow сообщает Automations о своих событиях — итог этапа, ответ на виджет, утверждённый Definition of Done, — и автоматизации с этими триггерами срабатывают; связь идёт по HTTP через [packages/automations-contract](../packages/automations-contract).
- Инструменты агента `read_flows` и `save_flow`: агент читает flow с каталогом навыков, исполнителей и шагов автоматизаций и сохраняет один flow — новый или на замену, на нужное место в списке. Этап с навыком или исполнителем не из каталога и шаг-скрипт без скрипта отклоняются, при отказе ничего не сохраняется; открытая страница Flow показывает сохранённое сразу. Из чего собирать flow, как подключать шаги Flow, свои скрипты и автоматизации Automations — навык `flow-create` в [skills](skills).
- «Исполнять» в виджете: первая колонка — «В этом треде», «Новый тред» (сосед исходного, как нативная передача bb) и «Дочерний тред» (тот же новый тред, но под исходным); дерево и ветка выбираются одинаково для обоих новых тредов. При «В этом треде» вторая колонка «Контекст» даёт «Сперва компактировать тред»: тред сжимается, и ответ виджета уходит агенту следующим сообщением очереди.
- Кнопка flow в композере нового треда рядом с выбором модели: тред идёт по выбранному flow — из него этапы в инструкциях агенту и в проверке виджета. Треды без выбора идут по первому flow в списке. Последний пункт списка — «Без flow»: Flow такому треду не вкладывает в ход ничего, и на кнопке остаётся одна иконка.
- Журнал решений: секция настроек «Хранение истории Flows» — путь по проекту, от корня рабочего дерева треда; не задан — `docs/flows`. Каждый ответ на виджет (не на уточнение) кладётся туда файлом — решение едет вместе с веткой и попадает в тот же PR, что и код, ради которого его приняли. У треда нет рабочего дерева — журнал молча не ведётся, ответу и реплике агенту это не мешает.

- Язык: настройка Language — System (язык браузера), English или Русский; на нём интерфейс, страница Flow и ответ в тред. Навык и инструкции агенту — на английском.

## Установка

```bash
cd bb-plugin-flow && npm install && bb plugin install "path:$PWD" --yes
```

Инструмент появляется в тредах, начатых после установки.

## Разработка

`npm test` — тесты, `npm run typecheck` — типы, `bb plugin build` — сборка бандла. Устройство и стыки — [docs/architecture/bb-plugin-flow.md](../docs/architecture/bb-plugin-flow.md).
