# @bb-plugins/layer-guard

Сторож слоёв: читает импорты пакета, находит рёбра между единицами (папки верхнего уровня и файлы в корне) и сверяет их с объявленным порядком слоёв. Тест плагина объявляет слои один раз и падает на любом импорте вверх, вбок внутри слоя или в папку, которой в слоях нет.

- `core.ts` — чистое ядро без ввода-вывода: разбор спецификаторов, разрешение относительных путей и алиасов, рёбра между единицами, нарушения порядка.
- `node.ts` — единственный стык с файловой системой: `readSourceFiles(root)` собирает исходники, пропуская `node_modules`, `dist`, тесты, папки `test-support/` и конфиги vitest.

Пример теста плагина:

```ts
const LAYERS: Layers = [["shared", "lib"], ["components"], ["views"], ["shell"], ["app"]];
const files = readSourceFiles(pluginRoot);
expect(formatViolations(layerViolations(crossUnitEdges(files, { aliases: { "@/": "" } }), LAYERS))).toBe("");
```

Type-импорты считаются рёбрами наравне с обычными: направление зависимости — свойство проекта, а не рантайма.

## Сторож git-установки

Общий пакет из `packages/` собирается внутрь плагина, но лежит вне его папки. Установка из git ставит `node_modules` только в папку плагина, а esbuild ищет пакет вверх от импортирующего файла, поэтому импорт значения из сторонней библиотеки в общем пакете роняет `bb plugin build`. Ни vitest, ни tsc, ни сборка в рабочем дереве этого не видят — у пакета там свои `node_modules`.

`bundledImports(files, HOST_SHIMMED)` возвращает такие импорты. Не считаются `import type` (esbuild его стирает), относительные пути и спецификаторы из `HOST_SHIMMED` — их `bb plugin build` подменяет рантаймом хоста. Сопоставление точное, как у самого bb: `react-dom/client` подменяется, `react-dom/server` нет. Список снят с bb 0.43.1 и принадлежит хосту.

Комментарии в разбор не попадают: фраза «import type» в комментарии не прячет импорт под ним. Границы сторожа: читаются только `.ts` и `.tsx` — `@import` в CSS, файлы `.js` и `require()` он не видит; относительный путь за пределы пакета тоже не проверяется.

Сторонние библиотеки общему пакету передаёт плагин пропом; тест пакета держит обещание:

```ts
const files = readSourceFiles(fileURLToPath(new URL(".", import.meta.url)));
expect(bundledImports(files, HOST_SHIMMED)).toEqual([]);
```
