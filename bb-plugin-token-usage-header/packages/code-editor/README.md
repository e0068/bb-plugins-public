# @bb-plugins/code-editor

Поверхность кода на CodeMirror 6 и одно правило «каким языком читать файл».

Вынесено из `bb-plugin-projects`, где панель узла и колонка файла нарисовали
это первыми. Второй потребитель — режим Raw в
[md-doc-view](../md-doc-view) — повод зависеть вниз на одну реализацию, а не
скопировать её.

## Что внутри

- `CodeEditor` — сам редактор: нумерация строк, подсветка по грамматике,
  прыжок на строку, палитра из токенов bb (фон, гаттеры, выделение), поэтому
  он живёт в любой теме без собственной палитры. Цвета самих токенов
  синтаксиса — готовый набор: дефолтный в светлой теме, One Dark в тёмной, —
  потому что у bb нет токена для «ключевого слова».
- `languageOf` — чистая таблица «расширение → грамматика». Расширение и есть
  весь ответ: нюхать содержимое пришлось бы до того, как выбран редактор, а
  единственный случай, где расширение врёт, — скрипт без суффикса, и он
  показывается как текст, чем и был до появления редактора.
- `useHostColorMode` — какую палитру рисует хост сейчас. Отвечает
  `color-scheme` на корне, а не догадка по именам классов bb: хост, который
  себя темизует, объявляет его в любом случае — нативные скроллбары, поля
  формы и фон холста читают именно его.

## Почему CodeMirror, а не Monaco

Monaco хочет веб-воркеров, которых бандл плагина не везёт, и весит в
несколько раз больше ради панели, которая читает один файл за раз.

## Зависимости

Пакет не импортирует CodeMirror значением ни в одном файле, и это сторожит
`git-install.test.ts`. Резолвинг esbuild идёт от каталога импортирующего файла
вверх, а установка плагина из git ставит `node_modules` только в папку плагина:
импорт, написанный здесь, искал бы в `packages/code-editor/` и падал бы с
«Could not resolve».

Поэтому модули собирает плагин. В его `libraries.ts` лежат импорты
`@uiw/react-codemirror` и `@codemirror/*`, сами пакеты — в `dependencies`
плагина, а готовый `CodeMirrorKit` приходит сюда обязательным пропом `kit`.
Передавать надо одну константу уровня модуля: расширения пересобираются при
смене набора. В `codemirror-kit.ts` набор описан только через `import type`,
который esbuild стирает.

Все объекты редактора строятся из одного набора, то есть из одной копии
`@codemirror/state`. Граница «Unrecognized extension value in extension set …
multiple instances of @codemirror/state are loaded», на которой редактор падал
при рендере, пока пакет держал свою копию, больше не пересекается.

`peerDependencies` называют модули, которые плагин обязан поставить, включая `@codemirror/state`: объявленный у плагина явно, он остаётся одной копией на весь набор.
`devDependencies` нужны только тестам: `test-support/codemirror-kit.tsx`
собирает набор так же, как это делает плагин.

`useHostColorMode` подписывается на `matchMedia` сам, а не через хук
дизайн-системы плагина: пакет лежит ниже любого плагина, а `components/ui`
плагина — выше. Десять строк подписки — цена того, чтобы не зависеть вверх.
