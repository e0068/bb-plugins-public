# Триггеры и действия плагина Pull Request

Машинерия плагина — не код, а таблица правил. Строка таблицы — теги триггеров слева и теги действий справа. На триггер плагин берёт **все** строки, где он есть, и выполняет их действия по порядку строк, затем тегов. Нажатие кнопки — триггер. Отображение — тоже действия, трёх видов: **кнопка** (`show.*`), **уведомление** (`notify.*`) и **статус треда** (`status.*`, значок в строке треда в сайдбаре). Прогон их не выполняет: кнопку применяет подписка шапки, уведомления — фильтр тостов клика, статус — скрипт сайдбара. Владелец правит таблицу на странице плагина, секция «Триггеры и действия»; агент — двумя инструментами:

| Инструмент | Что делает |
| --- | --- |
| `pr_automation_read` | Каталог id триггеров и действий, текущие правила в JSON и нумерованной таблицей, ошибки строк |
| `pr_automation_save` | `{ rules: { version: 1, rules: [...] } }` заменяет всю таблицу; `{ reset: true }` возвращает правила по умолчанию. Отвечает сохранённым, в том же виде, что и чтение |

Правила хранятся в версии 2; версия 1 и старое действие `show.row-glyph` при чтении мигрируют сами. Правка всегда идёт так: прочитать, изменить JSON, сохранить **целиком**, проверить в ответе, что строк с `problem:` нет. Сохранение сразу видно в открытых окнах bb. Неизвестные id при сохранении молча отбрасываются — сверяй имена с каталогом из ответа.

## Каталог

| Триггер | Когда срабатывает |
| --- | --- |
| `click.pr` / `click.pr-merge` / `click.pr-merge-archive` | Кнопка Pull Request и два пункта её меню |
| `click.merge` / `click.merge-archive` | Кнопка Merge и пункт Merge then Archive |
| `click.archive`, `click.ff`, `click.wake`, `click.retry-main` | Done & Archive, Fast Forward, Wake Up, Retry на бейдже «main not pulled» |
| `state.open`, `state.env`, `state.thread-pr`, `state.poll` | Шапка треда открыта; изменился git окружения; bb обновил PR треда; каждые 20 с |
| `outcome.pr-created`, `outcome.merged` | Сразу после успешного `git.create-pr` / `git.merge` |
| `outcome.mutated` | В конце прогона, если выполнилось хоть одно действие |

| Действие | Что делает |
| --- | --- |
| `show.wake`, `show.ff`, `show.pr`, `show.merge`, `show.main-not-pulled`, `show.archive` | Кнопка: на каждый триггер своей строки перезапрашивает своё состояние и появляется, только если условие выполнено (Wake Up — окружение в retiring; Fast Forward — ветка отстала и без своих коммитов; Pull Request — есть изменения и нет PR; Merge — PR открыт; main not pulled — Merge скрыт и последний pull main провалился; Done & Archive — PR смёрджен и дерево чистое) |
| `status.uncommitted`, `status.committed`, `status.pr-open`, `status.pr-checking`, `status.pr-conflict`, `status.pr-reviewed`, `status.pr-merged` | Статус треда: значок в строке сайдбара в этом состоянии. Скрипт сайдбара опрашивает сервер сам раз в 20 с, поэтому статус показывается, только если его строка держит `state.poll`; состояние без своего тега — значок скрыт |
| `notify.result` | Уведомление: успех клика с деталями и ссылкой на PR |
| `notify.warnings` | Уведомление: каждое «не получилось» — версия, переустановка, задача, bb CLI |
| `notify.prompts` | Уведомление-вопрос о репойнте плагина с кнопками |
| `notify.errors` | Уведомление: отказ RPC или проваленный шаг после созданного PR |
| `git.create-pr` | Открыть PR через API GitHub без push |
| `git.merge` | Смёрджить PR (squash), дождавшись вердикта mergeability |
| `git.pull-main` | Подтянуть локальный main; провал — бейдж «main not pulled», прогон не прерывает |
| `git.fast-forward` | Перемотать ветку треда на main |
| `files.bump-versions` | Поднять версии задетых `bb-plugin-*` коммитом на голову PR |
| `bb.tasks-in-review`, `bb.tasks-done` | Перевести связанные с тредом задачи |
| `bb.archive` | Архивировать тред |
| `bb.wake` | Разбудить тред (снимает застрявший retiring) |
| `bb.reinstall` | Переустановить плагины, задетые смёрдженным PR |
| `bb.refresh` | Серия обновлений шапки |

## Семантика, которую надо держать в голове

- **Порядок — это порядок строк и тегов.** Строки хранятся сгруппированными по виду первого триггера (клик, состояние, исход, без триггера); внутри группы — в порядке таблицы.
- **Исход выполняется сразу.** `git.merge` → действия строк с `outcome.merged` → остаток исходной строки. Поэтому по умолчанию main подтягивается до архивации.
- **Каждый триггер и каждое действие — не больше раза за прогон.** Повтор действия в двух строках не выполнит его дважды; циклы между исходами обрываются сами.
- **Отказ останавливает всё.** Отвергнутый мёрдж или архив — дальше ничего, и `outcome.mutated` не срабатывает. Исключение (например, перемотка невозможна) — прогон прерывается, но `outcome.mutated` срабатывает.
- **Архив без мёрджа перед ним проверяет готовность до начала прогона** — ни одна задача не отмечается, если тред не готов к архиву.
- **`bb.reinstall` требует `files.bump-versions` и `git.merge` в том же прогоне** — иначе пишет проблему в ответ мёрджа и ничего не ставит.
- **Уведомления работают только в строках кликов.** Клик показывает тост, если его вид (`notify.*`) есть в действиях строк этого клика. Убрать `notify.result` у Merge — успех мёрджа молчит, ошибки остаются.
- **Строка кнопки — это «перепроверь», а не «покажи».** Триггер строки заставляет кнопку спросить своё состояние; покажется она только при своём условии. Pull Request, Merge, main not pulled и Done & Archive взаимно исключают друг друга условиями, а не правилами.
- **`bb.refresh` ставь после `bb.reinstall`.** Обновление, запущенное до переустановки, не знает, что плагин сейчас обновит сам себя, и оставит таймеры на устаревшем хэндле — тост «used a stale API handle». По умолчанию оно висит на `outcome.mutated`, в самом конце.
- **Показ без триггеров не работает.** Действие `show.*` в строке без триггеров — кнопка скрыта. Убрать `state.poll` из строки показов — кнопки перестанут замечать PR, смёрдженный вручную на GitHub.
- **Клик, у которого пропал обязательный результат, отвечает ошибкой.** Pull Request без `git.create-pr`, Retry без `git.pull-main` — ошибка с названием недостающего действия.

## Типовые правки

| Просьба | Правка |
| --- | --- |
| «Не подтягивай main после мёрджа» | Убрать `git.pull-main` из строки `outcome.merged` |
| «При Merge сразу отмечай задачи done» | Добавить `bb.tasks-done` в строку `click.merge` после `git.merge` |
| «Спрячь Fast Forward» | Удалить строку `state-show-ff` |
| «Не показывай значок смёрдженного PR в сайдбаре» | Убрать `status.pr-merged` из строки `state-show-row-glyph` |
| «Не показывай успех мёрджа» | Убрать `notify.result` из строк `click.merge` и `click.merge-archive` |
| «Не трогай задачи при создании PR» | Убрать `bb.tasks-in-review` из строк `click.pr` и `click.pr-merge` |
| «Верни как было» | `pr_automation_save` с `{ reset: true }` |

## Новый триггер или действие в коде

1. Id и подпись — в `TRIGGER_IDS`/`TRIGGERS` или `ACTION_IDS`/`ACTIONS` в `src/core/automation.ts`; если меняется поведение по умолчанию — строка в `DEFAULT_RULES`. Тест в `src/core/automation.test.ts`.
2. Действие-эффект — функция в `actionEffects` в `server.ts`: пишет результат в `RunRecord`, отвечает `{ ok: true, emits? }` или `{ ok: false }` на отказ. Показ — id в `usePolledState(..., show)` у кнопки.
3. Клик — RPC зовёт `runClick(threadId, "click.<id>")` и собирает ответ из записи прогона; фронт показывает тосты через `useClickNotify()("click.<id>", …)`, а виды уведомлений по умолчанию — в `CLICK_NOTIFICATIONS`.
4. Исход — эффект кладёт `outcome.<id>` в `emits`.
5. Обновить таблицу каталога в этом навыке и раздел «Триггеры и действия» в `plugin-docs/pull-request-architecture.md`.
